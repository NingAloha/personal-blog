## 前言

我第一次接触电脑大概是在六岁。那年家里搬了新家，也配了一台装着 Windows XP 的电脑。最开始其实连鼠标都不大会用，只知道左键，看到家长在桌面上点一下右键，弹出来一个菜单，再点一下刷新都会觉得很酷，甚至有点像是什么隐藏操作。

后来会开浏览器了，就开始玩 4399、洛克王国之类的网页游戏。那时候上网基本上就是想到什么搜什么，搜索结果里哪个排在前面就点哪个，下载软件也是一样。我爸还给电脑装了 360，用久了以后也就知道，这东西大概是“防止电脑出问题”的，桌面上还有个花里胡哨的加速球，没事就会点两下，看着数字下去一点，总觉得电脑也跟着健康了一些。

至于它到底做了什么，我当然不知道。那个时候电脑对我来说差不多就是这样的东西，会亮，会动，点一下就会发生点什么，出了问题似乎也总有另一个按钮能解决，基本和魔法没什么区别。

## 游戏大概是最早的老师

上小学以后有了微机课。高年级的学长会拿 U 盘往机房电脑里拷游戏，所以机房里的电脑也就有了三六九等，有 GTA 的总是最抢手的，印象里主要是 GTA 3 和 Vice City，尤其是 VC。

机房其实是有网络的，我们当然也试过自己下载，不过游戏太大了，一节课眼看都快下完了，下载进度还在那里磨磨蹭蹭。后来也就慢慢知道为什么学长会拿 U 盘来，原来软件并不是什么点一下就凭空出现的东西，它还得从别的地方一点点搬过来。

那个时候也接触过不少盗版游戏盒子，现在想想它们在“方便”这件事上其实做得非常彻底。打开以后就是一排游戏，点一下安装，等一会就能玩，文件是从哪来的、放在哪里、为什么不需要买，这些问题根本不会出现在用户眼前。

我当然也从来没想过这些。

中间还出过一次比较大的事故。父母那时候会管着玩电脑，平时得等他们上楼输完密码才能用。有一回实在想玩，又没叫他们过来，我就自己开机在那里瞎按。那时开机过程里还能比较直接地看到一些启动选项，我也不知道自己进了哪里，反正东按西按一通，最后把系统给重装了。

我爸放在电脑里的备考复习资料也一起没了。

好在他没打我。

当然这件事并没有让我从此学会什么数据备份、磁盘分区之类的东西，顶多就是知道以后别在那个界面乱按。很多东西在不知道原理的时候，其实照样可以操作，只不过偶尔会付点学费。

## R O O T

除了电脑，那几年自然也一直在用手机，Android 和 iOS 都用过。和电脑比起来，手机的东西明显整合得更完整，有自己的应用商店，要什么进去搜就好了。

Android 用久了以后“内存”会不够（那时候我也和大多数人一样，把存储空间都叫“内存”，后来才知道叫错了）。想删几个不用的软件，却发现有些系统自带的东西怎么都删不掉，于是第一次听说了一个东西，R O O T。

我当时甚至不会把 `root` 当成一个单词读，就是一个字母一个字母地拼。只知道有了这个 ROOT，就能删掉那些原本不让我删的软件。

iPhone 倒省心得多，没有那么多乱七八糟的东西，我也就没怎么折腾。硬要说的话，那时还能装一些盗版游戏，下载安装以后还要按照教程跑去设置里点一个叫开发者证书还是什么的东西，反正教程怎么写就怎么做。

后来盗版越来越不好装，一些平台开始分享装了游戏的 Apple ID，我又照着教程登录、下载、退出。也就是在这个时候，我对“账户”这种东西有了点模模糊糊的认识，原来软件好像不完全就是电脑里或者手机里的一堆文件，它还和某个账号、某个权限有关。

不过“购买软件”这种概念那时还是很淡的。在我的认知里，软件大概就是网上有，找到就能下载。

## 然后被流氓软件教育了一遍

游戏盒子虽然方便，但也不是什么都有，找不到的时候还是得去网上下载。

然后自然就碰到了那个年代很经典的 P2P 下载器、下载站和捆绑安装。本来只想装一个东西，一路下一步点完以后，桌面上突然多出来三四个完全不认识的软件。

多来几次也就学聪明了，慢慢知道安装的时候要看看页面上有没有什么小勾选框，而且那些勾选框还经常默认就是选中的。一不小心装错了就去软件管家里卸载，后来又听说火绒比较干净，于是把 360 换掉了，再后来懂得更多以后直接就不用了，有时他们反而还会是很多操作的阻碍。

现在回头看，这大概算是我最早的一点“电脑环境管理”，只是那时候肯定不会用这个词。说白了就是被坑得多了，知道别什么都往电脑里塞。

## 原来电脑不只有 Windows

后来家里又搬家，买了一台 2015 款的 MacBook Air，不过到我手里的时候已经装好了 Windows 10，所以我也就一直这么用。

而且在那以前，我一直以为电脑就只有 Windows。

不是知道 macOS 但没用过，是真的不知道。

所以虽然手里拿的是苹果电脑，我也完全没有觉得哪里不对。直到有一次开机又开始瞎按，突然弹出来一个系统选择的界面，除了 Windows 之外还有一个我不认识的系统。我点了进去，这才第一次看到 macOS。

也是到那个时候我才知道，原来电脑和操作系统不是一回事，同一台机器上甚至可以有两套完全不同的系统。

后来游戏玩得多了，又发现有些游戏在这台电脑上就是卡，才慢慢知道原来电脑本身还有性能差别，CPU、显卡、内存、硬盘这些东西也不是所有机器都一样。

现在看起来这些都算最基础的概念，不过很多东西第一次知道的时候，并没有什么系统的学习过程，就是生活里突然碰到一下，于是脑子里多出一个词。

## Steam、GitHub，还有越来越多奇奇怪怪的东西

2018 年左右《绝地求生》很火，我稀里糊涂听别人说只能在 Steam 上玩，于是又瞎捣鼓注册了 Steam 账号。后来又有人说哪个平台送游戏，我也去注册、去领，过了很久才知道当时那个平台原来叫 GOG。

Steam 里的游戏有些要收费，我自然就先玩免费的，不过从那个时候开始，我确实慢慢往正版这边靠了。软件不再只是一个“哪里能下”的问题，还开始出现平台、账号、游戏库、付费这些东西。

Steam 有时又会连不上，于是继续上网找办法。记得当时有一个叫 Dogfight360 的 hosts 修改工具，点几下就能解决。原理是不知道的，反正点点就能用了。后来又知道有一种东西叫加速器，也是开了就能用。手机上其实也有类似经历，有的游戏国内应用商店没有，别人说得先装 Google 服务，Google 一直加载，就再下一个叫蓝灯的软件。

那个时候我完全没想过，电脑上这些 hosts、加速器，手机上的蓝灯，背后其实多少在碰同一类问题。它们名字不一样，界面也不一样，在我脑子里自然就是几件完全不同的东西。

再后来用到了 Clash，那时候还是 Clash for Windows。容我怀念一下，我到现在都觉得 CFW 那个界面比现在一些套着浏览器壳子的客户端好看。

第一次打开 Clash 的时候一个新词又一次出现在我的世界里：订阅链接。那时我常常上网搜免费的用，免费的通常活不了多久，死了就再找新的。反反复复下来，脑子里倒是慢慢留下了几个词，`Clash`、`node`、订阅，只是仍然不知道它们到底是怎么回事。

再到疫情的时候家里要上网课，家里一台电脑不够用，于是又要买。那时候我第一次发现同一台电脑居然还有两个价格，一个正常版，一个便宜几百块的“Linux 版”。最后买了 Linux 版，然后又重新装成 Windows，当然也不是我自己装的，不过“Linux”这个词从那时候开始也正式进到脑子里了。

同一时期我也越来越爱折腾 Windows，装 Office，家庭版升级专业版，各种乱七八糟的教程，也是在这个过程中知道了 KMS，知道有一个经常连不上、而且满是英文的网站叫 GitHub。

我最开始真把 GitHub 当成了另一个应用市场，只不过这个应用市场长得很奇怪。点进一个软件以后，页面上不是一个大大的下载按钮，而是一栏栏文件，真正能下的软件反而藏在一个小小的入口里。后来才知道，那个地方叫 Releases。

那些 Windows 教程里也经常会冒出 CMD 和 PowerShell。以前我一直觉得操作电脑就是拿鼠标点点点，到这个时候才知道，原来还有一种方法是在黑底窗口里输入一串东西。

不过那些命令在当时的我眼里和咒语也没什么区别。教程让我复制，我就复制；让我粘贴，我就粘贴；按下回车没报错，就算成功。

## 配环境

后来上大学学软件工程，第一门编程语言是 C。

学 C 的第一步还是配环境。

于是我就打开 CSDN，搜教程，别人怎么写我就怎么做，为什么这么做也不知道，反正先做了再说。

一开始用 CLion，写 C 其实没遇到什么太大的问题。后来有些考试环境是 VS Code，于是又装了 VS Code，结果点 Run 就报错。继续上网搜，有人说要在 VS Code 设置里填什么路径，有人说要改系统环境变量，我还是照着做。

最后能跑了，也就没再管。

整个大一差不多都是这样。开发环境肯定是有的，代码也确实能写，但你要问我电脑到底怎么找到编译器，PATH 到底是什么，CLion 为什么不太需要折腾而 VS Code 又为什么要配这些，我是说不清楚的。

事实上就连 IDE 和编辑器到底有什么区别，我都是到最近才真正建立起比较清楚的认识。

不过当时一套东西既然能跑，也没有什么继续折腾的必要，于是大一就这么过了。

## Minecraft

真正变化很大是在大二上。

那段时间因为一些情感问题，整个人状态不大好，成天泡在电脑前。朋友拉我一起联机玩 Minecraft，最开始我们也是去找各种现成工具做内网穿透，当然“内网穿透”这个原理是后来才知道的，当时还是属于软件开开、两边填填，然后看看能不能连上。

然而效果不怎么样。

后来看到网上还有人专门收费帮别人搭 Minecraft 服务器，我就想，那为什么不自己搞一个？

于是打开 B 站。

然后一下子又冒出来一大堆以前没怎么接触过的东西，Linux、服务器、SSH。最开始我连 `nano` 怎么保存都不知道，`cd`、`Ctrl+O`、`Ctrl+X` 一点点上手。服务端跑起来以后开始写 `sh` 脚本，要控制运行内存就往启动参数里塞东西，服务器崩了想让它自己重启，又开始写循环和计数。

老实讲，大一其实学了一堆东西，但我一直不知道那些东西到底能拿来干嘛。到了这里才第一次很明显地感觉到，原来学的东西真的可以拿来解决问题。

这个感觉挺不一样的。

大二上快结束的时候又知道了 Ubuntu。我不太喜欢一直“在系统里跑一个系统”，那样子真的很笨重，风扇呼呼转。于是我开始折腾双系统，也就这样碰到了分区、UEFI、引导这些东西。再往后就不停折腾各种系统，服务器和 Linux 也越来越熟。

很多东西其实并不是我专门找本书从头学到尾学会的。通常都是先用，出了问题，再查，然后慢慢才知道自己之前到底在做什么。

## AI

差不多也是这个阶段，AI 开始越来越好用。

我就跟着 AI 学。

以前遇到问题还是搜网页，看教程，后来开始可以直接问 Copilot，哪里不懂就接着问。

再后来我突发奇想，既然服务器都能自己搭，那为什么不干脆自己搭网络环境？

于是跟着 Copilot 没日没夜折腾了三天，终于搭成了第一个 SS 节点。

现在回头看，这种东西大概十来分钟就能搞定，当时硬是折腾了三天。

节点搭好以后又开始写配置，也就是从这里才真正一点点理解规则、分流这些东西。网络大部分时间当然是正常用的，但偶尔就会出现一些很奇怪的问题，明明网络没有坏，这个软件能用，那个软件不行，于是又开始接触 TUN、系统代理、端口。

端口其实早在搭服务器的时候就已经用了不知道多少次，不过很长时间里，我对它的理解差不多就是“一段有范围、两边要配对的随机数字”。严格来说好像也不能说完全错，但到这里才算是开始知道监听、连接这些词到底在说什么。

Fake IP、DNS 劫持、DNS 污染、MITM 这些也是后来一点点补起来的，有些甚至就是前不久才真正理解。

有时候回头看会觉得挺好玩的，好多概念其实我早就“用过”很多年了，只是当时并不知道自己用的东西叫什么。

## 软件开始变成一种需要付钱的东西

随着开始订阅 AI 服务和一些国外服务，又不得不进入另一个以前完全陌生的领域。国内平时不怎么用信用卡，于是 Visa、礼品卡、账号区域、购汇、拒付、风控这些东西又一点点学上了，我也办了自己第一张 Visa 信用卡。

软件这边也开始主动买正版、订阅服务。

GitHub 学生认证一直没过的时候，我自己花过每个月 10 美元订 Copilot。那个时候 Copilot 里的 GPT-4 还几乎可以随便用，我就是天天跟着它学。后来 GitHub 调整方案，我才转去订 GPT。

就在这个月，我还花了七百多买了 iOS 和 Mac 两份 Surge。

小时候觉得软件就是网上随便下的东西，后来到处找免费的节点，现在反而开始愿意为了长期稳定、体验好而且自己确实会一直用的工具付钱。这个变化也不是哪天突然想明白的，只是用着用着就这样了。

无私的开源和对正版闭源付费的支持，在我看来两种方式各有优长，共同铸就了这个辉煌的信息时代。

## 十年以后又买了一台 MacBook Air

大二下的时候，我越来越觉得游戏本那一套已经不太适合自己的学习需求，于是又买了一台 MacBook Air，M4，2025 款。

刚好和家里那台 2015 MBA 差十年。

这回倒是完全不一样了。十年前拿到 Mac，我连 Mac 原来有自己的操作系统都不知道；十年后再买，我很清楚为什么要 Mac，也知道自己想拿它做什么。

也是在这台机器上，我才真正开始对包管理这件事有比较完整的认识。

其实以前装服务器、折腾双系统的时候早就用过 `apt`，但那时我的理解一直很像“Linux 里的应用市场”。买 Mac 以后装 Homebrew，后面又碰到不同语言版本的问题，再和 GPT 聊到 mise，这时候才开始慢慢意识到，包管理器处理的不只是“帮我把软件下载下来”。

这个软件从哪来，装在哪里，以后怎么升级，哪个版本正在生效，应该由谁负责管理，这些其实都是环境的一部分。

后来又开始接触 Makefile。它严格来说当然不是普通的 shell 脚本，更像是在描述构建目标、依赖和命令，不过我真正觉得有意思的倒不是终于能给 Makefile 下定义，而是以前学到的一堆零零散散的东西终于开始串起来了。

函数、文件、编译、脚本、依赖、Git、服务器，以前一个个都是孤零零的知识点，后来突然发现它们是能一起工作的。

差不多这个时期我也写了好几版个人博客，推翻、重写，再推翻，最后慢慢变成现在相对固定的这一版。为了让个人网站真正跑起来，又接触到 Cloudflare、CDN、DNS、域名、HTTPS、部署、CICD这些东西。

很多以前只是听过的词，慢慢都找到了自己的位置。

## 重装并没有解决问题

其实早在搭 Minecraft 服务器那段时间，我就已经有一次受不了自己的 Windows 环境了。

这里一个工具，那里一个环境，有些东西不知道装在哪里，有些设置不知道是哪篇教程让我改的，有些东西明明很久不用了又不敢删，因为完全不知道删了会影响谁。

最后狠下心重装了系统。

那时候想得也很简单，既然乱了，那就重新来一次。

现在回头看，那次重装当然是有用的，至少把很多历史垃圾直接一锅端了，但它其实没有解决最核心的问题。因为我虽然比以前更会配环境了，本质上还是把过去那些东西重新装了一遍。

该跟教程还是跟教程，该复制命令还是复制命令，只不过熟练了一点。

一台刚装好的系统天然很干净，但只要继续按以前的方式用，不知道东西是谁装的、为什么装、由谁管理，过一段时间自然还会重新变得乱七八糟。

## 最后居然又绕回了说话

订阅 ChatGPT后，我最开始当然也就是一次次单独的对话，这里问一个问题，那里再问一个问题。后来有了 Projects，我开始把同一个主题的聊天放在一起，课程、开发环境、服务器、网络、软件，慢慢地也就形成了现在这套和 GPT 协作的方式。

电脑环境这边尤其明显。

以前通常是出了问题再问，现在会先看机器上到底有什么。这个工具是谁装的，现在实际调用的是哪一份，有没有重复，它为什么还在这里，删掉以后会影响什么。修改之前先看，修改以后再验证，最后把当前状态整理成一份维护档案。

这套东西到现在其实已经跑得挺成功了。

至少现在我再打开自己的电脑，不会像以前一样只知道“它反正能跑”。

Mac 上哪些东西归 Homebrew，哪些语言版本交给 mise，系统自带的工具为什么还留着，某个项目具体依赖什么，我基本都能找到答案。服务器也是一样，服务跑在哪里、谁负责启动、端口为什么开放、配置放在哪，都有相对清楚的记录。

绕了一圈以后，我发现自己最后反而又回到了最简单的一种交互方式：

自然语言。

> “为什么我这里有两个 Python？”
>
> “这个东西是谁装的？”
>
> “这个项目为什么跑不起来？”
>
> “我想写 Java，现在应该怎么装？”

这些话显然比先去学一遍包管理、PATH、Shell、运行时管理再开始操作容易得多。

只是我不想让这种方便重新变成小时候的“魔法”。

小时候我点一下 360 加速球，不知道发生了什么；照着教程改 hosts，也不知道发生了什么；往 CMD 里粘贴一串命令，还是不知道发生了什么。

如果现在换成一句话交给 AI，然后 AI 在背后装了一堆东西，最后只告诉我“已经完成”，那其实只是把原来的按钮换成了聊天框。

我想要的并不是这个。

我希望自然语言只是入口，下面的东西仍然是清楚的。AI 可以帮我做，但至少应该能够告诉我它装了什么、装在哪里、为什么这么做、以后谁负责更新，现在真正生效的是哪一个。

最近整理自己的几台电脑和服务器时，我也越来越觉得，“干净”其实不是最准确的说法。

两份 Python 不一定就是重复，系统自带的工具和 Homebrew 装的工具也不一定只能留一个；有时候同一个软件出现好几份，本来就有各自的职责。

真正让我难受的一直不是“东西多”。

> 是我不知道它为什么在那里。

如果一台电脑上的东西都能解释清楚，知道来源、用途、位置和管理方式，那即使它很复杂，我觉得也还是清楚的。反过来，一台刚重装完什么都没有的电脑当然很干净，但如果从第一天开始就继续看到什么装什么，半年以后还是会回到原来的样子。

所以我想把现在这套方法整理下来。

先不做什么新的软件，也不急着发明一套新的工具。现成的 GPT Projects 其实已经足够把这件事做得很好，我想先写一篇教程，估计不久之后就能发出来。我会试着说明怎么从一台刚装好的电脑开始，一边使用，一边把环境维护得清楚、透明，而且自己始终知道发生了什么。

至于再往后，如果这套方法真的足够稳定，也许我会专门再写一个插件，或者一个专门干这件事的 Agent。

不过那都是后话了。
